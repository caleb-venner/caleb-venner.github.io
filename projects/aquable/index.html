AquaBle: Chihiros aquarium devices in Home Assistant

A Home Assistant integration that speaks the Bluetooth LE protocol of Chihiros lights and dosing pumps, with its own dashboard cards to schedule, monitor and control them, so the vendor's phone app is no longer needed.

Caleb Venner · v4.1.0 · MIT · Code on GitHub

Chihiros make aquarium lights and dosing pumps that are controlled through the vendor's phone app over Bluetooth. That keeps them separate from the rest of a home automation setup: no shared dashboards, no automations, and no way to tie them into anything else.

AquaBle is a Home Assistant integration that talks to the devices directly over Bluetooth LE. It has grown into a full replacement for the app, covering more than a dozen light models and the four-head dosing pump.

Talking to the hardware

Chihiros devices use a Nordic UART service over BLE, with a small binary framing protocol on top: a preamble, a command ID, a message ID, the parameters and an XOR checksum. AquaBle encodes and decodes those frames itself, and identifies each model from its advertised Bluetooth name.

The foundation for this came from Michael Dietrich's open-source Chihiros LED Control project, which had already worked out how to drive the lights. I built on that work, extending it to the dosing pump and a wider range of light models using captured Bluetooth packet traces and analysis of the official apps. That work added the eight-step sequence the doser expects when a schedule is configured, and the telemetry packets that report each pump head's mode, schedule, dosed volume and lifetime total. Everything is written up in the repository's protocol notes.

The integration uses Home Assistant's own Bluetooth stack, so it works through local adapters or ESPHome Bluetooth proxies anywhere in the house, and reconnects automatically.

Treating devices as configuration, not switches

Home Assistant tends to model everything as entities you turn on and off. Aquarium equipment doesn't work that way: the light and the pumps run their own schedules on their own microcontrollers, and only need to be told what to do. So AquaBle treats them as configuration targets.

Schedules are stored in Home Assistant as the source of truth and pushed to the hardware, which then runs them on its own. Telemetry comes back as ordinary sensors, so dosing volumes and schedules can drive automations like anything else. The light's live channel brightness is calculated locally by interpolating its schedule, which keeps sensors updating every second without polling the light over Bluetooth.

Dashboard cards

To replace the app properly, AquaBle ships two custom Lovelace cards, written in JavaScript and CSS and registered automatically when the integration is installed.

The light card draws a 24-hour ramp profile as an SVG curve for every colour channel, with a marker for the current time. Schedule slots can be added, edited or deleted, each with its own dawn and dusk times, ramp duration, active weekdays and peak level per channel. A manual tab switches between auto, manual and off, with sliders for each channel.

The doser card shows each of the four pump heads with today's dosed volume against its daily target. Heads can be switched on or off, dosed by hand in steps as small as 0.1 mL, and given a daily target, run time and set of weekdays.

The latest release adds light sync: one light can act as a master, and its schedules and commands are mirrored to other lights of the same model.

Where it led

Working at the protocol level also showed the limits of the approach. AquaBle can only do what the factory controller allows, over a Bluetooth link to firmware I can't see inside. That's what led to my ESP32 controller, where I replaced the light's controller entirely.
